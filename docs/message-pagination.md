# صفحات الرسائل والبحث والترتيب

`GET /api/messages?page=1&limit=12&sort=newest&q=` يتطلب Cookie دخول صالحة. الحساب يؤخذ من الجلسة فقط؛ لا يمكن اختيار صاحب الرسائل من الطلب.

| المتغير | الافتراضي | القيم المقبولة |
| --- | --- | --- |
| page | 1 | رقم صحيح من1 إلى1000000 |
| limit | 12 | رقم صحيح من1 إلى50 |
| sort | newest | newest أوoldest |
| q | فارغ | نص بحث بطول200 حرف كحد أقصى بعد إزالة الفراغات الطرفية |

البحث يبحث في نص جميع رسائل الحساب قبل اختيار الصفحة، وغير حساس لحالة الأحرف. الأحرف % و_ و\ تعامل كنصوص بحث عادية وليست wildcards. أي رقم أو ترتيب أو صيغة غير صالحة، بما فيها تكرار معاملات البحث، ترجع400. اتجاه SQL يختار من قيم ثابتة، والبحث والأرقام تمرر كمعاملات.

الرد يحافظ على `success` و`data` كمصفوفة رسائل، ويضيف `pagination` وفيها page وlimit وtotal وtotalPages. total هو عدد النتائج بعد البحث، وليس عدد رسائل الصفحة. عدد الصفحات لا يقل عن1؛ الحساب أو البحث الفارغ يرجع data: [] وtotal: 0 وpage: 1 وtotalPages: 1.

الترتيب يستخدم created_at ثمid بنفس الاتجاه لضمان ترتيب ثابت عند تساوي التاريخ. العد والصفحة يستخدمان لقطة قاعدة بيانات واحدة. إذا طلبت صفحة بعد آخر صفحة متاحة، يرجع آخر صفحة موجودة بدل صفحة فارغة. هذا يعالج حذف آخر رسالة في الصفحة الأخيرة.

الواجهة تعرض12 رسالة، وتعيد البحث والترتيب إلى الصفحة الأولى. تؤخر الطلبات250 مللي ثانية أثناء الكتابة وتلغي الطلب السابق حتى لا تظهر نتيجة بحث قديم. بعد الحذف والتعديل تعيد جلب نفس الفلاتر لملء الصفحة وتحديث العدد؛ تعديل النص قد يخرج الرسالة من نتائج البحث الحالية.

لإضافة فهرس الحساب والتاريخ والرقم على قاعدة موجودة، نفّذ `npm run db:setup`. الفحص: `node scripts/test-message-list.js`، ببيانات مؤقتة تُحذف تلقائيًا.
