# الجلسات وتجديد الدخول

- Access Token: JWT مدته15 دقيقة، مرتبط برقم جلسة sid، داخل Cookie access_token بخصائص HttpOnly وSameSite=Strict وPath=/api وSecure في production.
- Refresh Token: قيمة عشوائية عالية العشوائية، داخل Cookie refresh_token بخصائص مماثلة وPath=/api/auth. قاعدة البيانات تحفظ SHA-256 لها فقط، ولا يرجع أي توكن في JSON.
- الجلسة تنتهي بعد7 أيام من تسجيل الدخول، ولا يمدد التجديد موعدها النهائي. آخر Access Token وCookie تجديد يقصّران إلى المدة المتبقية إذا كانت أقل من15 دقيقة.

## السيرفر

POST /api/auth/login ينشئ auth_sessions وسجل بصمة في refresh_tokens. الدخول من نفس المتصفح يبطل الجلسة السابقة التي تحملها Cookies، لكن الجلسات المستقلة بأجهزة أخرى لا تتأثر.

POST /api/auth/refresh يتحقق من بصمة التوكن والجلسة وموعد انتهائها، ويستبدل التوكن مرة واحدة داخل transaction مع قفل الصفوف. يحتفظ ببصمات التوكنات المستخدمة لكشف إعادة استعمالها. الرد200 يحتوي user وexpiresIn فقط، وتصل Cookies الجديدة عبر Set-Cookie.

إعادة تقديم توكن مستخدم خلال5 ثوانٍ ترجع409 دون إصدار توكن آخر أو مسح Cookies؛ هذا يمنع إبطال جلسة سليمة بسبب طلبين متزامنين. بعد هذه المهلة، إعادة استخدام توكن معروف سابقًا تبطل جلسته وترجع401. التوكن المجهول لا يبطل جلسة أخرى. التوكن المنتهي أو الجلسة المبطلة يرجعان401 ويمسحان Cookies من المتصفح الذي أرسل الطلب.

POST /api/auth/logout يبطل الجلسة في قاعدة البيانات ويمسح الـCookies، حتى إذا انتهى Access Token وبقي توكن التجديد. توقيع توكن الدخول يتحقق منه قبل قبول sid لأغراض الخروج. كل مسار محمي يراجع وجود الجلسة وصلاحيتها، لذلك أي نسخة قديمة من Access Token ترفض بعد الخروج مباشرة عند الطلب التالي. عملية بدأت قبل الخروج قد تكتمل.

الجلسات مرتبطة بالمستخدم بـON DELETE CASCADE، والبصمات مرتبطة بالجلسة بنفس الطريقة. يمكن تنظيف الجلسات المنتهية أو المبطلة القديمة دوريًا؛ لا توجد مهمة تنظيف تلقائية بعد. قبل الاستخدام شغّل npm run db:setup. التوكنات القديمة بدون sid تحتاج تسجيل دخول جديد بعد هذا التحديث.

## الواجهة

session-client.ts يجمع التجديد في طلب واحد لكل تبويب، ويستخدم Web Locks لتسلسله بين التبويبات، مع تسلسل محلي بديل. بعد انتظار القفل يعيد فحص /me حتى يستفيد من تجديد تبويب آخر. عمليات الدخول والخروج تستخدم القفل نفسه لمنع إصدار Cookies تجديد متأخرة بعد الخروج.

apiFetch يعيد الطلب المحمي مرة واحدة فقط بعد401 وتجديد ناجح. لا يعيد الطلب عند أخطاء الشبكة أو500 أو429، ولا يجدد تلقائيًا على login/logout/refresh. انتهاء الجلسة يبقي401 ويزيل حالة الدخول. مؤقت AuthProvider يجدد عند انتهاء Access Token بدل إخراج المستخدم، ويعيد المحاولة بعد30 ثانية عند فشل الشبكة.
